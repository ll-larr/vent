### Правка 1 — Унифицировать систему кнопок (приоритет: высокий)
Сейчас в кодбейзе hover-стили кнопок разрознены: slide-in оверлеи через `::before scaleX`, padding-shift, разнокалиберные тени и свечения. Свести всё к **трём типам** с одинаковой анимацией (crossfade `background/color/border-color` за `350ms ease` + сдвиг стрелки на `4px`):

- **Type A — `.btn.lime` (lime → cream)**: lime фон + чёрный текст по дефолту → на hover плавно перекрашивается в cream (`#f6f3ec`) + чёрный текст. Применяется: главные CTA на тёмных секциях, topbar CTA, hero «оставить заявку», «скачать прайс-лист», «Рассчитать» в svc-included и calc-card, «Позвонить сейчас» в success-state.
- **Type B — `.btn.ghost` на светлом + `.svc-card .more`**: прозрачный фон + чёрный текст + светлая обводка → на hover чёрный фон + лаймовый текст. Применяется: вторичные кнопки на светлом фоне, ссылка «в расчёт» в карточках услуг.
- **Type C — `.btn` дефолт (ink → ink + лайм-обводка/текст)**: чёрный фон + cream текст → на hover остаётся чёрный фон, но появляются лаймовая обводка и лаймовый текст. Применяется: «Полный расчёт» в мини-калькуляторе hero, «Отправить заявку» в форме, дефолтные «Оставить заявку»/«Рассчитать».
- **Type C variant — `.btn.ghost` на ТЁМНОМ фоне**: прозрачный фон + cream текст + полупрозрачная светлая обводка → на hover остаётся прозрачный фон, но обводка и текст становятся лаймовыми. Применяется в svc-included, calc-card, success-state («Отправить ещё одну»).

Точные hex, токены, тайминги, easing и anatomy всех кнопок (включая «не-`.btn`» пилюли `.now-cta` в hero и `.pl-cta` в карточке прайса) — в `README.md`, секция «Правка 1». **Удалить все устаревшие эффекты**: slide-in `::before scaleX(...)`, padding-сдвиги на hover, разноцветные box-shadow-свечения.

### Правка 5 — Success-state контактной формы (НОВОЕ)
Сейчас на проде после отправки формы «Заявка на выезд» показывается ломаный схлопнутый блок «Заявка принята» в узкой колонке без стилей. Нужно сделать **полноценную success-карточку**, которая:

- Занимает **то же место**, что и форма (та же ячейка bento, `grid-column: span 7; grid-row: span 3`)
- Имеет **тёмно-зелёный фон** (`var(--brand)`) с декоративным lime-radial-gradient в правом нижнем углу
- Содержит:
  1. Верхнюю meta-строку «заявка №`VNT-MMDD-XXXX` · принята»
  2. Лаймовую круглую иконку-чекмарк (56×56) с pop-анимацией
  3. Большой заголовок «Заявка _принята._» (em лаймом)
  4. Подзаголовок про «30 минут» и кликабельный телефон для срочных
  5. Список «что дальше» из 3 шагов с dashed-разделителями и таймингами справа лаймом (`01 Звонок инженера ~ 30 мин`, `02 Видеоосмотр и КП — в течение дня`, `03 Договор и выезд — 1–3 дня`)
  6. Подвал: слева «номер заявки» + крупный номер (моно-шрифт, tabular-nums), справа две кнопки — Type A «Позвонить сейчас» и Type C ghost «Отправить ещё одну» (сбрасывает форму)
- **Slide-up анимация** при появлении (`translateY(14px) → 0`, opacity 0 → 1, 0.55s)

**Критически важно:** добавить в CSS правило
```css
.ct-success[hidden]{ display: none !important; }
.ct-form[hidden]{ display: none !important; }
```
Иначе `display: flex` перебивает HTML-атрибут `hidden` и пользователь видит форму И success-блок одновременно (это был баг, который мы уже отлавливали — не повтори его).

Полная анатомия каждой части карточки (размеры, шрифты, цвета, отступы, dashed-borders, responsive поведение) — в README, секция «Правка 5».

### Правка 6 — Номер заявки в первой колонке Excel (НОВОЕ)
Номер заявки `VNT-MMDD-XXXX` должен **уходить на бэкенд первым полем формы**, чтобы в Excel/Google Sheets/CRM он попадал в **первую колонку** строки.

**Что нужно сделать:**
1. Внутрь `<form class="ct-form">` **первым** элементом (до всех видимых полей) добавить:
   ```html
   <input type="hidden" name="ticket" id="ct-ticket" value="" />
   ```
2. Сгенерить номер **на загрузке страницы** (а не на submit). Формат: `VNT-` + двузначный месяц + двузначный день + дефис + 4 случайные цифры. Пример: `VNT-0520-7421`.
3. Использовать **тот же номер** в success-блоке (в meta-строке сверху и в `.ref b` снизу).
4. После «Отправить ещё одну» — регенерить новый номер для следующей заявки.
5. **В production-обработчике submit** (там, где сейчас происходит реальный POST на бэкенд / в Google Sheets) — поле `ticket` уже будет в `FormData` первым. Убедись, что бэкенд / интеграция записывает его в **первую колонку** Excel/Sheets/CRM. Если бэкенд складывает поля по порядку получения — ничего менять не надо. Если по именам — добавь колонку `ticket` первой в схеме.

Полный JS-код генератора и handlers — в README, секция «Правка 6».

### Правка 7 — Плитка сроков в hero (НОВОЕ)
В hero на лаймовой статистической плитке (`.h-stat-2`) сейчас показывается «4–6 дн · средний срок под ключ». Это вводит в заблуждение — заявки бывают разные: срочный выезд делается за 3 часа, полный цикл «под ключ» — до 4 дней. Заменить **один усреднённый срок на диапазон**:

- Большое число теперь — «3ч → 4дн» (с заметной чёрной стрелкой между значениями, в том же дисплейном шрифте что и цифры)
- Подпись — «от срочного выезда до под ключ» (либо «в зависимости от объекта и услуг» — финальная формулировка на согласовании)

Технически:
- Уменьшить `font-size` числа с 56px до `clamp(34px, 3.4vw, 44px)` — строка длиннее, должна влезать в плитку без переноса (`white-space: nowrap`)
- Единицы измерения (`ч`, `дн`) — внутри `<small>` c `font-size: 0.55em`
- Стрелка `→` — отдельный `<span class="sep">` с `font-size: 0.75em`, `font-family: var(--display)`, `color: var(--ink)` (та же чернота, что у цифр) — чтобы стрелка читалась как равноправный элемент композиции, а не служебный символ
- Никаких изменений размера/позиции самой плитки в bento-сетке

Полная анатомия и markup — в README, секция «Правка 7».
