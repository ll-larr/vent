# Промпт для Claude Code

Скопируйте всё, что ниже разделителя, в Claude Code, запущенный в корне репозитория `vent`.
Перед этим положите папку `design_handoff_vent_landing/` в корень репозитория (рядом с `package.json`).

---

Ты работаешь в репозитории сайта Vent.team (Next.js 14 App Router, React 18, TypeScript, Tailwind 4, shadcn/ui, React Hook Form + Zod, vitest). Прочитай `CLAUDE.md` в корне — там команды, конвенции и текущая архитектура.

## Задача

Заменить текущий дизайн сайта (bento-modern) на новый — **скролл-историю**. Новый дизайн лежит в `design_handoff_vent_landing/`:

- `README.md` — полная спецификация: токены, типографика, сетки, посекционное описание, интеракции, формулы калькулятора, состояние. **Это источник истины.** Читай его целиком перед началом.
- `design/Vent - Лендинг-история.dc.html` — главная, 8 секций + футер
- `design/Vent - Статьи.dc.html` — список статей
- `design/Vent - Статья.dc.html` — шаблон статьи + контент 5 материалов
- `design/Vent - Мобильный вид.dc.html` — эталон мобильной вёрстки (390 px)
- `design/story-scroll.js` — vanilla-движок скролл-эффектов
- `design/img/`, `design/fonts/` — ассеты макета

HTML-файлы — **дизайн-референс, а не код для копирования**. В них есть рантайм прототипа (`support.js`, теги `<x-dc>`, `<sc-for>`, `<sc-if>`, шаблонные `{{ }}`, инлайновые стили на каждом элементе) — это переносить не надо. Переносить надо: вёрстку, размеры, цвета, типографику, тексты и логику из класса `Component` внизу каждого файла.

Открой `.dc.html` в браузере, чтобы увидеть дизайн живьём — файлы самодостаточны.

## Что делать по шагам

**1. Разведка перед кодом.** Прочитай `design_handoff_vent_landing/README.md`, затем текущие `src/app/page.tsx`, `src/app/globals.css`, `src/components/*`, `src/lib/pricing.ts`, `src/lib/calculator-context.tsx`, `src/data/articles.ts`. Составь план: что переиспользуется, что переписывается, что удаляется. **План покажи мне до того, как начнёшь писать код.**

**2. Токены.** Новый дизайн ломает часть текущих токенов в `globals.css @theme`:
- радиусы: в новом дизайне **только `999px`** (пилюли, кружки, бейджи) и `3px` у чекбокс-квадратика. Прямоугольные блоки — без скруглений. Токены `--radius-tile/-lg/-card` (22/28/14 px) в новой вёрстке не используются.
- добавляются: `#0e0d0c` (глубокий чёрный, подложка фото), `#191817` (ховер тёмных карточек).
- палитра `#f6f3ec / #141312 / #1e5c32 / #c8ff3e / #ffffff` — прежняя, не трогай.
- шрифты те же (Fraunces / Inter Tight / JetBrains Mono / Marggraff), способ подключения не меняй.

**3. Разделители карточных сеток — `gap:1px` на цветном фоне сетки, а не бордеры.** Иначе на стыках появятся двойные линии. Это в дизайне везде.

**4. Скролл-эффекты.** `design/story-scroll.js` — единственный файл, который можно перенести почти как есть. Варианты: подключить как есть в клиентском компоненте-обёртке или переписать в хук(и) в `src/lib/`. Важно сохранить: всё скролл-зависимое считается в **одном** `requestAnimationFrame` на `scroll`/`resize` (треки, параллакс, топбар, подсветка меню, прогресс-бар). Если размазать по разным слушателям — появится рассинхрон.
Активная секция определяется по линии `0.38 × высота вьюпорта`, не через IntersectionObserver.
Reveal-анимации — через IntersectionObserver, но с предохранителем: контент должен быть виден, даже если обсервер не сработал.
`prefers-reduced-motion` отключает reveal, параллакс, автопрогон слайдера и кастомный курсор.

**5. Секция 02 обязана деградировать** при `innerWidth < 900` или `innerHeight < 620`: sticky-трек становится обычным потоком, левая колонка с кадрами скрывается, все 6 шагов видны сразу. Без этого на коротких экранах шаги не долистываются.

**6. Калькулятор.** Формулы, коэффициенты и тарифы — в README (раздел «Формулы калькулятора»). Сверь их с существующим `src/lib/pricing.ts`: если расходятся — приведи к README и почини `pricing.test.ts`. Состояние калькулятора шарится между секцией 07 и формой (сейчас это `calculator-context.tsx` — переиспользуй). Пресеты по клику из секций 02 и 05 должны выставлять тип объекта + услуги и скроллить к секции 07.

**7. Маршруты.**
- `/` — главная (скролл-история).
- Статьи: в репозитории уже есть `src/app/blog` и `src/data/articles.ts`. Проверь текущие URL и **сохрани их** (не ломай индексацию); если решишь мигрировать на `/statyi/<slug>` — сделай это отдельным шагом с 301-редиректами и обнови `sitemap.ts`.
- Контент 5 материалов лежит в объекте `DATA` в `design/Vent - Статья.dc.html`. Тексты **переносить дословно**, не переписывать. Типы блоков (`p / h / quote / list / img / pair / note`) описаны в README — сделай под них рендерер.
- Существующие `/calculator`, `/contacts`, `/privacy` не трогай, кроме приведения к новому визуалу.

**8. Картинки.** Все фото — в `public/images/` с русскими именами. В макете используются переименованные копии; таблица соответствия — в README, раздел «Ассеты». Перенеси файлы в латиничные имена (`hero-main.jpg`, `tech-01-diagnostics.jpg`, `obj-restaurant-1a.jpg` …) и используй `next/image`. Русские имена в путях в проде — источник проблем с кодировкой.

**9. Форма заявки.** Поведение, валидация и состояние «отправлено» описаны в README. Бэкенд уже есть (`src/app/api`, `src/lib/sheets.ts`) — подключи к нему, прототип ничего не отправляет.

**10. Проверка.** После каждого крупного куска: `npx tsc --noEmit`, `npm test`, `npm run build`. Визуально сверяйся с `.dc.html`, открытым рядом. Веди список расхождений «референс vs порт» в `AUDIT.md`, как это уже принято в репозитории.

## Порядок работ

Секциями, снизу вверх по риску: сначала каркас (топбар, прогресс-бар, футер, токены), потом простые секции (03, 04, 06, 08), потом статьи, потом калькулятор + форма (07), последними — сложные скролл-секции (01, 02, 05).
Не делай всё одним коммитом. После каждой секции — сборка и коммит.

## Критерии приёмки

- Все размеры — `clamp(min, preferred, max)` из README, не фиксированные пиксели.
- Ограничения длины строки в `ch` сохранены.
- Mono-текст всегда uppercase с трекингом.
- Слайдер «до/после» работает мышью, тачем и стрелками, имеет `role="slider"` и `aria-valuenow`; на каждый таб объекта — три пары «до/после».
- Кнопка формы неактивна, пока не заполнены имя, телефон и согласие на обработку ПДн.
- FAQ: открыт всегда ровно один пункт, повторный клик закрывает.
- Мобильный вид совпадает с `Vent - Мобильный вид.dc.html`.
- `npm run build` и `npx tsc --noEmit` проходят чисто.

## Чего не делать

- Не копировать HTML прототипа в компоненты как есть.
- Не переносить `support.js`, `ios-frame.jsx`, теги `<x-dc>` / `<sc-*>` / `<x-import>`.
- Не переписывать тексты — вся копирайтинг-часть финальная.
- Не добавлять скруглений прямоугольным блокам.
- Не менять палитру и шрифты.

Начни с чтения README и плана. Вопросы задавай до начала работы, а не в процессе.
